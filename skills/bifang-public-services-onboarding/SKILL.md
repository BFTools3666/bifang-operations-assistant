# 毕方个人 CloudBase 接入向导

## 单独调用时的首条回复

只发送 `$bifang-public-services-onboarding`、点击技能入口，或问“有哪些功能／怎么用”时，先完成本地源码定位，首条业务回复只展示以下菜单，等待客户选择。即使会话里有旧接入记录或客户项目已打开，单独再次调用也展示菜单。

1. **接入统计和更新** — 为桌面项目首次接入日活统计、版本更新，可选一项或两项。
2. **更新版本** — 管理已接入应用，查看当前更新、发布新版、切换推荐或强制、取消或重新设置更新。

请回复 **1** 或 **2**，也可以直接说明想做什么。

客户回复编号或功能名即完成分流。选 1 进入首次接入；选 2 进入已有应用版本管理。展示菜单时只读取技能规范，等选择后再提环境问题或查询应用状态。若客户调用时已给出明确任务（含明确继续某一门禁），直接按该任务进入对应流程。

## 首次接入适用环境

首次接入默认使用 PostgreSQL + 官方 pgdoc Document 插件，开始第一/第二门禁前读 [PostgreSQL 适配](references/postgresql.md)。数据库类型自动核验，不再要求客户填写；第一门禁只读探测，插件缺失留第二门禁按选择和具体计划启用。旧文档库共存或部分安装必须停止，不自动迁移、清空或升级。

本 Skill 当前仅面向个人自行管理的 CloudBase 免费体验环境。定位本地规范后，先按客户意图选择流程。不要从其他分支或本机旧版同名 Skill 补入未定义流程。

## 自动定位本地规范源码

每次调用先按 [本地源码定位规则](references/local-source.md)，从本 Skill 实际目录运行 `scripts/local-source.mjs resolve`。安装时已自动记录本地仓库位置，正常调用不让客户填写路径；未绑定或仓库移走才进行有限查找，无法唯一确定时才询问。定位成功后完整读取返回的源码 SKILL.md，本轮规范、references、模板与工具全部来自同一已核验个人版源码，不能把客户项目目录当成规范仓库。安装副本和源码不同时采用源码并说明版本；不自动拉远端、切分支或使用公司版。

此定位只核验规范来源，不扫描客户项目，不增加门禁或替代任何门禁确认。安装/更新本 Skill 使用该源码根目录的 `npm run skill:install`，不触发接入问答。

## 根据客户意图选择流程

- 首次接入项目的更新或统计，或明确继续接入中的某一门禁，走下方五道门禁及第六步实机验收。首次开始时完整读取 [第一门禁与开通指引](references/personal-cloudbase.md)。
- 已接入应用需要查看、发布、取消或调整版本更新，直接走 [已接入应用的版本更新管理](references/personal-release-management.md)。先查所选发布流当前设置与客户端实际结果，再按客户选择交付详情或设置文件，确认具体差异后写入并验证。已有明确目标和动作直接复用。
- 已接入应用反馈「统计有数据，大屏只显示英文 ID」时，直接走[大屏名称核对与修复](references/shared-function-extension.md#已接入应用的名称修复)。复用已填的 `app_id` 和 `display_name`，只读定位差异，向客户展示本次需要确认的修复。
- “更新一下”如果无法从项目、会话及对象判断，展示上方两个功能选项并等待选择。指向 Skill 自身的更新、设计或流程说明按维护请求处理。

客户负责提供只有自己知道的信息、在云平台完成身份操作，以及确认具体选择和影响。助手负责读项目和本任务回执、查当前状态、预填文件、拟定文案、执行校验和已确认的动作。每次先做完能自动完成的工作，再把缺项集中在一条消息里。客户已经说明目标、动作和新值时直接准备审阅结果。只读详情直接交付；当前设置已符合要求时给核验结论。

给客户的确认以“目标＋改了什么＋谁会受影响＋确认后执行什么”为主。唯一明确的待审计划可以回复“确认执行”，由助手记录客户原话并绑定完整计划标识。多个平台用平台名称列出各自差异，可一次确认明确列出的同一批计划，部分确认只执行对应目标。各门禁的先后顺序、请求与 UI 的独立确认、云端写入前的具体计划确认继续适用。

以下门禁适用于首次接入。

## 第一门禁

选定首次接入后，先问：“你是否已经在自己的腾讯云账号下创建好了 CloudBase 免费体验版环境？请选择：已创建 / 尚未创建 / 不确定。”复用明确回答。未创建按 [完整开通与密钥指引](references/personal-cloudbase.md) 展开注册、实名、零元申请和环境创建步骤；不确定先查看套餐。**已有环境只通过环境子项，不能直接通过第一门禁。**

随后引导客户在 CAM 创建/复用专用子用户、在第一门禁同时关联检查策略和创建策略，进入子用户 API 密钥页创建或复用 SecretId/SecretKey。reference 包含两份可直接导入的完整策略与权限范围，创建策略含共享函数配置更新 `scf:UpdateFunctionConfiguration`。旧子用户核对已关联策略的生效内容，缺少时只补这一项；已有等价授权直接复用。创建权限在第一门禁准备；RunCommands 有写能力、策略作用于账号资源，不能误称单环境纯只读权限。管理密钥不能替代客户端运行时凭据，也不默认使用主账号长期密钥。

运行 `cloudbase:personal:init` 创建仓库外受限 resource-input.json，给客户真实绝对路径。客户在本机填写环境信息和密钥，回复“已填写”后，按已说明范围运行 `cloudbase:personal:access -- --file <实际路径>`，只读检查环境、套餐和额度；不回显密钥原值、片段或摘要。

环境确认、检查与创建权限均已关联的依据、私有密钥交接和 access-verified 全部完成才通过。只读检查不能证明写接口已实测，不为核验权限提前创建资源。仅填好文件、只有 SecretId、密钥过期/权限不足都不通过。第一门禁只收集环境与管理凭据，不扫描客户项目、不收集应用/发布流参数、不创建云资源或写业务代码。维护 Skill 不触发真实凭据收集和云请求。

## 第二门禁

统计保留改为普通索引＋定时清理，先读 [清理资源与免费核验](references/retention-cleanup.md)。它包含专用清理函数、timer 和未来到期记录删除；旧 TTL 计划不覆盖新增资源。只改规范/只读检查不激活清理，方案变化先展示完整新计划并等待确认。旧任务按新增 action 补权限差异，不重建身份或轮换密钥。

第一门禁通过后完整读取 [资源清单、手动/自动创建与检查](references/personal-resources.md)。复用第一门禁密钥文件，自动补项目事实，先向客户完整展示统计函数、更新函数、统计大屏及集合/索引/HTTP 路由的实际名称、作用、默认配置和已有/缺少状态，再让客户明确选择“自己手动创建 / 助手自动创建并检查 / 已有资源仅检查”。未选择不写入云端。

- 手动创建：用 prepare 离线生成客户专属函数 ZIP 和私有配置，给真实文件链接与完整步骤；等待客户告知完成后用 verify 只读检查，不擅自转自动创建。
- 自动创建：先 plan 输出精确目标与最新免费预检，复用覆盖该计划的明确自动创建授权，apply 逐项创建并读回；不再重复问“是否开始”。选择时若只有概览，则先补齐计划再确认一次具体计划。直接复用第一门禁已准备的检查/创建权限与原密钥，不再安排补关联策略；权限失效时返回第一门禁修复。
- 已有资源：只跳过创建，不跳过核验；使用原材料或真实部署依据做限定只读核验，不覆盖、轮换或重建。未知、冲突或异构适配不足不能视为通过。
- 必需资源全部有核验依据才通过；客户声明已建、文件已填、命令退出 0 或旧 skipped 输出均不算通过。交付逐项结果、私有材料/回执路径及尚未验证的真实 HTTP/大屏/EXE 项。

从自动定位并再次核验的源码根目录使用 `cloudbase/personal/cli.mjs`。第一门禁 init → access；第二门禁 validate → plan 后，手动走 prepare → 客户完成 → verify，自动走已授权 apply → 逐项及最终读回。独立 Skill 包不含整个源码，缺少时按定位规则处理，不运行默认公司分支部署器。[resource-input.template.json](assets/resource-input.template.json) 只能复制到私有目录后交付，不在仓库内填密钥。

共享函数已服务其他应用时，按 [共享函数增量接入](references/shared-function-extension.md) 处理。计划列出新应用 ID、预期中文名、现网大屏读取名称的位置，以及受影响的旧应用。支持配置名称的大屏在同一计划中追加应用和中文名。旧版从函数包读取名称，缺项时展示具体修复计划。第二门禁核验部署配置，第六步分别核验真实接口和页面上的名称。

## 第三门禁

第二门禁通过后，完整读取 [参数与请求确认](references/personal-client-confirmation.md)。确认本次客户端仅更新、仅统计或都接入的范围，复用明确选择；先自动识别项目事实、第二门禁产出和适用默认值，只让客户补缺项。

用 `cloudbase/personal/client-confirmation.mjs init` 创建仓库外私有输入文件并给实际路径，客户补齐后用 `preview --file` 离线读取并生成请求。更新使用已部署 application-version-api 的 GET 与两项 runtime 请求头；统计使用无客户端密钥的十字段 POST。不能套用公司外部更新服务或混入 CAM/管理凭据。模板见 [integration-input.template.json](assets/integration-input.template.json)。

参数完整后，回复正文分别展示每个所选服务的实际 URL、方法、请求头、路径/query/body 全字段、值或动态规则、来源、默认行为与待验证事项。密钥只存私有文件，完整含密钥实例另存同目录，正文使用脱敏预览并给文件链接。然后等待客户明确确认当前 confirmation_id 的明细；“已填写”和脚本成功不等于通过。所选两项须整体通过，等待时不编码、不发送请求；实质变化重新确认。

## 第四门禁

第三门禁整体通过且确认内容仍有效后，读取 [UI 确认与项目实施](references/personal-client-implementation.md)，严格执行 **4A UI 确认 → 4B 架构/规范核验 → 4C 编码 → 4D 本地验收**。每项通过后才进入下一项；更新和统计都选时，更新 UI 等待确认期间也不先实现统计。

先观察目标项目实际页面、组件、主题与交互风格，展示普通更新、强制更新、手动检查入口的可见预览；列出真实触发/显示位置、按钮和关闭行为、强更新业务限制清单。预览只用模拟数据，不能提前改业务入口。必须等待客户明确确认本版 UI；第三门禁的参数确认不能代替 UI 确认。仅统计且无可见 UI 变更时，记录依据后将 4A 人工确认标不适用；若改隐私说明或可见状态，仍先预览确认。

UI 适用项通过后，完整阅读目标项目及修改目录的 AGENTS.md、架构与编码约定、真实调用链和同类实现，说明复用组件、HTTP/配置/状态/错误/日志/异步机制、拟改范围及验证命令。4B 是自动核验，不新增审批；已有客户端实施授权时直接按项目架构编码和本地验收，不再问是否开始。仅文档/只读/暂不实施限制仍有效，不能用简单 UI 确认解除。

可信服务职责由 Rust 实现，保持当前前端栈与模块边界；参数和凭据仍按第三门禁私有文件规则处理。个人版更新当前是 GET 与外部链接交付，不能借旧公司协议虚构 block_new_operations、目标版本、安装进度或安装成功。采用假凭据、模拟接口、固定时钟和临时状态本地验证并修复；真实服务测试、发布部署、制品打包/安装等保持对应授权边界。只维护本 Skill 时不实施客户业务代码。

## 第五门禁

第四门禁本地通过后读取 [确认保存与更新预检](references/personal-update-preflight.md)。助手预填已有真实发布信息及待确认的默认文案，客户只补缺项。资料齐全时直接本地校验并展示精确自动保存计划，客户确认后使用已有版本管理 API 保存、管理读回，再执行同计划已说明的更新 GET 预检。客户只需补信息和确认，不要求其手动调用 API；明确选择手动或已自行发布时才复用该分支。

需要客户填写文件时，先创建或核验本任务仓库外受限文件，正文给实际绝对路径及可点击链接，逐项列出完整字段路径、填写含义、必填/可选和预填值保留说明。第五门禁使用独立发布交接文件；“已填写”只触发本地校验，不是云端写入授权。校验后给出计划标识、准确 POST/PUT 目标及完整载荷、私有链接、凭据角色、读回与预检范围，再请求客户确认；已有同一具体计划授权直接复用。

确认后复核输入绑定，managementWrite 负责保存、managementRead 负责查重/读回、runtime 负责限定 GET，三者不混用。不自动覆盖冲突记录，不在写入结果不明时盲目重试，不直写数据库、不上传包、不改权限。计划中记录新增或修改及真实 id（适用时），修改必须有明确差异授权。成功保存并读回后直接执行已确认的预检，无须客户再手动发布。具体流程、当前成功响应合同和失败边界以 reference 为准。

预检要求 HTTP 200、七字段合同、code 映射、下载链接本地匹配及预期行为一致；检查响应不含目标版本号，不能冒充从 runtime 接口读回。此阶段不请求下载链接、不下载/安装/运行制品、不发送真实统计。所选目标全部预检通过才进入第六步；客户明确分平台推进时记录本轮范围和其余待验证目标，不将局部通过当成整体通过。仅统计记本门禁不适用。

第五门禁计划中一并说明后续当前项目的构建、运行和基础联网测试范围；已确认覆盖这些动作时，第五门禁通过后直接进入 [第六步构建与制品测试](references/personal-artifact-testing.md)，不再问是否开始。客户后续明确要求直接构建并测试时复用该授权。只授权保存/预检或仍有暂不运行限制时，仅补真正缺少的动作范围；规范修改本身不扩大历史授权。

## 当前产出与停止位置

交付五道门禁状态、证据类别、资源清单、私有文件位置、请求/UI 确认、架构与本地验收记录，以及适用的客户配置完成反馈和更新预检结果。第三门禁通过只表示参数确认，第四表示本地通过，第五表示限定更新预检通过或仅统计不适用。第六步基础构建和实机测试按对应 reference 执行；完成后同一条最终回复必须主动给出测试结果、实际制品链接、统计大屏实际地址及当前客户的大屏登录 Token，未验证项和交付缺项如实列明，仅更新时大屏项不适用。凭据读取及交付边界见 [第六步交付](references/personal-artifact-testing.md#交付)。下载/安装升级和回退仅在相应范围授权后扩展。

目标是云函数检测版本并返回外部下载地址，不存储或中转安装包。第三门禁明确使用个人资源工具所部署函数的运行时合同；其他已有合同须先核验适配，不能虚构地址、默认凭据或可用性结论。

## 授权边界

开户、实名、零元订单、平台授权、CAM 策略关联和密钥创建由客户在腾讯云页面完成。第一门禁准备并读取私有文件，按已说明范围只读核验；第二门禁先选择方式，再按精确计划授权自动创建和检查。文件填好不自动授权云写入，维护规范不读取真实凭据。打包、发布、推送或删除保持对应具体授权；第二门禁的私有函数 ZIP 是部署材料，不是客户端 EXE 打包授权。出现费用或升级要求停止，不创建第二个免费环境、不删除旧环境换资格。

只要求维护 Skill 时，修改规范并验证文档，不实际开展客户问答或云操作，也不读取真实客户凭据。除第六步最终向当前客户交付其 `dashboard.DASHBOARD_ACCESS_TOKEN` 外，不把账号、身份证件、Token、Cookie、SecretId/SecretKey 写入回复；任何凭据原值均不得写入代码、日志或仓库。该例外不包括统计查询 Token、版本服务密钥或 CAM 密钥，具体按第六步交付规则执行。
