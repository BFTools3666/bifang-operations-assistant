# 毕方小工具公共服务 3.0 接入指南

## 先看结论

每个小工具在自己的项目中只发一句：

```text
https://gitlab.kuajingvs.com/qiuyang/bifang-operations-assistant.git 帮我接入
```

向导会验证并安装权威 Skill，读取当前项目，保留 `daily_active` 遥测，把未公开的旧静态更新实现直接替换为 application-version API v1，并运行本地验证。无需先记 Skill 名称，也不需要保留两套更新协议。

这句话只授权当前客户端里的 Profile 和接入代码变更。CloudBase 部署/删除、打包安装、真实 GUI E2E、发布、推送、购买仍是独立动作，必须在对应门禁中执行。

## 版本与权威来源

- 基础设施：`3.0.0`
- 接入 Skill：`2.0.0`
- Application-version 契约：`1.0.0`
- 机器入口：[`../bifang-onboarding.json`](../bifang-onboarding.json)
- Bootstrap：[`../tools/bootstrap_bifang_onboarding.py`](../tools/bootstrap_bifang_onboarding.py)
- Skill：[`../skills/bifang-public-services-onboarding/SKILL.md`](../skills/bifang-public-services-onboarding/SKILL.md)
- API：[`../contracts/application-version-api-v1`](../contracts/application-version-api-v1)
- 应用登记：[`../cloudbase/apps.json`](../cloudbase/apps.json)

Git 仓库是唯一权威。飞书、Word、压缩包或旧客户端里的文字不能覆盖当前仓库。Skill frontmatter 的 `infrastructure-source-commit` 必须指向一个实际包含 3.0 基础设施的祖先提交；`application-version-baseline-commit` 固定记录服务端 v1 实现基线。

## URL 一句话如何工作

1. 记录当前客户端 cwd、Task、Git 分支、HEAD 和工作区状态。
2. 对规范 GitLab URL 执行只读 `git ls-remote --symref`；在客户端之外的隔离目录获取权威仓库，不建 submodule、不复制进业务源码。
3. 核验 checkout 是 Git top-level、origin 精确匹配规范 URL、整个仓库相对 HEAD 干净、所需源文件均受 Git 管理且不含符号链接/重解析点、`.pyc` 或 `__pycache__`，并要求本地 HEAD 精确等于远端默认分支实时 advertised HEAD。
4. 保持 cwd 位于原客户端 Git 仓库内，运行权威仓库的 bootstrap 并传入该客户端根目录；bootstrap 先扫描，以客户端分支、HEAD、index、porcelain 状态和扫描范围内容摘要复核客户端未变，再安装 Skill，最后统一输出阶段 0 结果。
5. 同一轮完整读取已安装 Skill，继续写 Profile v2 和迁移客户端，不要求用户再输入 `$bifang-public-services-onboarding`。

Bootstrap 自身不改客户端；真正的客户端修改由安装后的 Skill 在原 cwd 中完成。权威源码与目标客户端不能重叠；目标客户端可以位于 `CODEX_HOME/worktrees/`，但不能与实际 Skill 安装目录重叠。来源不符、源码全仓不干净、HEAD 不是远端当前默认提交、同名 Skill 无法证明为当前规范版本或精确已发布的 v1 / 2.1 树、基础设施来源提交不实、HEAD 低于基线、路径含符号链接/重解析点、Python bytecode/cache 或必需文件缺失时，必须停止，不能拼凑版本。bootstrap 安装路径不会执行 `CODEX_HOME`、用户目录或环境变量指定的外部 `quick_validate`。

## 只读扫描

向导先运行：

```text
python <skill-root>/scripts/scan_project.py <project-root>
```

Windows 使用：

```powershell
py -3 -X utf8 -B <skill-root>\scripts\scan_project.py <project-root>
```

扫描和人工代码审查共同确认：

- 框架、语言和正常启动入口；
- 唯一 SemVer 来源；
- 平台、架构与发布渠道；
- AppConfig、本地匿名身份和每日门禁；
- 主窗口 ready hook、安全外链与完整退出；
- 当前 APP_ID 和 telemetry 路由；
- 旧静态更新客户端、URL、14 字段 parser、rollout 与兼容开关；
- 新 application-version Base URL、认证头和 code；
- Git 中用户已有改动。

`scan_incomplete=true` 时必须列出跳过文件，不能声称旧协议已经删除。脏工作区不等于失败，但向导不能 reset、clean、stash、切分支或覆盖用户改动。

## Profile v2

档案路径固定为 `.bifang/public-services-profile.json`。它保存非敏感接入事实：产品、APP_ID、框架、平台/架构、版本来源、生命周期钩子、CloudBase 公网地址、telemetry endpoint、application-version Base URL、发布流、基础设施来源、认证绑定的非敏感 ID/状态、门禁和阶段。

关键字段：

```json
{
  "profile_schema_version": 2,
  "update_transport": "application-version-api-v1",
  "application_version_contract_version": "1.0.0",
  "application_version_base_url": "https://<平台默认域名>/tools/version-control/v1",
  "release_streams": [
    {
      "platform": "windows",
      "architecture": "x64",
      "channel": "stable",
      "code": "bifang-example-windows-x64"
    }
  ],
  "legacy_update_status": "removed"
}
```

Profile 不得保存 Key、Secret、Token、Cookie、Authorization、数据库凭据、账号、硬件 ID、本机绝对路径或任何敏感值/摘要。旧 Profile v1 先只读验证与对照，再在规范一句话授权下生成确定性的 v2；无证据的字段保持未知，不能为了过校验填假值。

写后运行：

```text
python <skill-root>/scripts/validate_profile.py .bifang/public-services-profile.json
python <skill-root>/scripts/derive_resources.py --profile .bifang/public-services-profile.json
```

## 客户端迁移

保留正确的 `daily_active`：应用专属 AppConfig、APP_ID 隔离、联网前落盘、北京时间同日一次、失败不重试。只替换版本协议：

```http
GET https://<平台默认域名>/tools/version-control/v1/versions/{code}/{currentVersion}
x-app-key: <runtime key>
x-app-secret: <runtime secret>
```

客户端严格解析冻结的裸七字段 JSON 响应，映射无更新、提示更新、强制更新和停止更新。标题/正文按不可信纯文本显示；下载地址再次验证为安全公网 HTTPS；强制更新退出走宿主完整清理路径。

必须删除：

- 旧静态更新 Base URL 与 manifest 路径；
- 14 字段 manifest parser/types；
- 本地 rollout、min-supported 与旧强制更新判定；
- 双协议、fallback、兼容开关；
- 只验证旧实现的测试、夹具和文档。

可以保留并复用：严格 SemVer、安全 URL、主窗口异步时序、UI、外链和完整退出。

客户端凭据只允许 `versions:check`。管理读取使用独立的 `versions:read + ads:read` 凭据，管理写入使用另一份 `versions:write + ads:write` 凭据，二者绝不进入客户端。服务部署配置必须覆盖每条登记发布流，并全局保留一份不可导出的 `contract-ads-*` 凭据执行 `ads:show` 契约测试。凭据从项目已有的安全本地注入层读取，原值不进 Git、Profile、源码、普通日志、命令行参数或截图。

## 八个阶段

阶段号标识当前交付结果，不是必须顺序累积的进度条。阶段 5 只依赖本地 Profile、客户端实现与测试，可以在阶段 4 云部署前完成；阶段 6 才要求真实服务、运行凭据、构建制品和 GUI E2E。Profile 的 `legacy_client_update_removed` 只证明客户端旧代码已删，`legacy_cloud_resources_removed` 只在阶段 8 的精确线上退役完成后为真。

| 阶段 | 可验证结果                          | URL 一句话授权         |
| ---- | ----------------------------------- | ---------------------- |
| 0    | 权威来源验证与只读扫描              | 是                     |
| 1    | Profile v2                          | 是                     |
| 2    | 运营精灵登记 APP_ID/code            | 否，运营精灵任务       |
| 3    | CloudBase 配置与只读计划            | 否                     |
| 4    | 服务部署与公网 HTTP E2E             | 否，写入前再次确认     |
| 5    | 当前客户端替换/删除旧协议与本地测试 | 是                     |
| 6    | 构建、安装、真实 GUI E2E            | 否，另有明确要求       |
| 7    | 发布与推送                          | 否，写入前再次确认     |
| 8    | 线上旧静态资源删除                  | 否，精确预检后再次确认 |

一个客户端 Task 的 URL 一句话是阶段 0+1+5 的单一“完成客户端接入”结果。它不横跨到另一个客户端，也不把 mock、编译或 HTTP 测试冒充真实 GUI E2E。

## 两个实际客户端

### 鼠标精灵

- APP_ID：`bifang-mouse-clicker`
- 平台流：Windows x64 stable
- 建议 code：`bifang-mouse-clicker`
- 接入 Task 必须以用户明确确认的当前 working tree 为权威；不能 `reset`、`stash`、`clean`，也不能从旧 HEAD 另起导致改动丢失。实际版本和工作树状态在任务开始时实时核对，本指南不冻结一次性快照。
- 最终使用新构建的准确 Windows EXE/安装包验证更新状态、错误状态、完整退出和不再请求旧协议。

### 录屏助手

- APP_ID：`bifang-screen-recorder`
- Windows code：`bifang-screen-recorder-windows-x64`
- macOS code：`bifang-screen-recorder-macos-arm64`
- 两个平台的构建配置必须静态绑定自己的 code，不能运行时猜平台。
- 本机只可形成 Windows 真实 E2E；macOS 必须在真实 Mac 上保持独立 `Unverified`，直到取得原生证据。

两个项目都没有广告 UI 时，客户端接入只验证版本运行端点；广告和管理端点由运营精灵服务端契约 E2E 覆盖，不为凑接口新增产品功能。

## 云端与费用门禁

只复用负责人确认的现有免费 CloudBase 环境和平台默认 HTTPS 域名。不创建第二环境，不购买域名、证书、套餐或资源包，不开启按量超限、超限扣费或自动续费。

阶段 4 和 8 前必须重新只读枚举远端函数、路由、集合、权限、索引、hosting 文件、默认域名和费用状态，展示精确创建/更新/删除目标与回滚方式，再等待负责人明确“继续”。任何非零金额或升级提示立即停止。

## 安装与验证 Skill

从经过验证的权威仓库运行：

```powershell
py -3 -X utf8 -B skills\bifang-public-services-onboarding\scripts\install_skill.py
```

Installer 会校验 Skill 结构、2.0/3.0/1.0 版本、来源提交、规范 GitLab URL 和隐式触发策略；拒绝 `.pyc` / `__pycache__`、来源不明的同名 Skill、版本降级或同版本不同内容；只为精确匹配权威已发布树的 v1 / infrastructure 2.1 Skill开放迁移，并通过暂存和可回滚替换原子升级，不改其他 Skill。bootstrap 会显式禁用安装器的外部 `quick_validate` 搜索，避免执行未由本次权威 checkout 证明的脚本。

## 报告证据

每轮交付都要列出实际修改、删除的旧协议文件/符号、Profile 与资源派生、测试命令和结果，以及明确未执行的部署、安装、GUI、发布、推送、购买或线上删除。真实 E2E 证据必须绑定准确制品 SHA、进程/窗口、最终请求 URL 和遮挡凭据后的结果。
