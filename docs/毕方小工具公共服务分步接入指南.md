# 毕方个人 CloudBase 分步接入指南

在项目会话单独发送 `$bifang-public-services-onboarding`。首条回复展示 **1. 接入统计和更新**、**2. 更新版本**，选定后进入相应流程。也可以在调用时直接说明任务。

个人环境默认 PostgreSQL，通过官方 pgdoc 插件承载统计、更新和大屏。数据库自动识别、两份 CAM 策略、插件创建与读回、旧库保护均遵守 [PostgreSQL 适配规范](../skills/bifang-public-services-onboarding/references/postgresql.md)，不新增客户必填数据库参数。

已接入项目要查看详情、推荐改强制、取消或重新设置更新时，先查远端当前记录和客户端结果。查看详情直接返回。目标明确时，助手自动准备文件和计划，一次展示变更及生效范围。资料齐全时直接回复“确认执行”，缺项才需补填。确认后助手远端保存并验证。见[已有项目的版本更新管理](../skills/bifang-public-services-onboarding/references/personal-release-management.md)。

首次接入定义五道门禁，必须依次通过，第五门禁通过后才进入第六步 EXE 测试。开通步骤以 [个人免费 CloudBase 指引](../skills/bifang-public-services-onboarding/references/personal-cloudbase.md) 为准，Skill 入口为 [SKILL.md](../skills/bifang-public-services-onboarding/SKILL.md)。

先下载 `codex/personal-cloudbase` 分支的完整源码（Git 或 ZIP），在其根目录运行 `npm run skill:install`，自动安装/更新并记录源码位置，无须填写固定盘符或目录。之后在客户项目调用 `$bifang-public-services-onboarding 请按门禁帮我接入本项目。`。Skill 自动核验绑定目录并加载本地最新规范，工具在该源码目录运行，业务接入目标仍是客户项目。来源定位不算新门禁，也不允许提前扫描客户项目；仅在找不到或无法唯一确定源码时补问路径。详见 [本地安装与定位](../skills/bifang-public-services-onboarding/references/local-source.md)。

1. 先确认客户自己的 CloudBase 免费体验环境；未创建则完整给注册、实名、零元申请和环境创建步骤，已有则跳过开户指引。
2. 已有环境只完成环境子项。按第一门禁 reference 引导 CAM 专用子用户，同时关联检查与创建两份策略，再准备 API 密钥并准确交接 SecretId/SecretKey。两份策略均已关联的依据是第一门禁通过条件，不把创建权限留到第二门禁。
3. 助手先 init 创建仓库外私有 resource-input.json 并给真实路径；客户本机填写环境和密钥，不在聊天发送。
4. 已说明只读范围、客户告知填写完成后，运行 access 检查凭据签名、免费环境、套餐与额度。只有这些条件全部通过才进入第二门禁，不扫描客户项目或提前创建资源。

第一门禁通过后进入 [第二门禁](../skills/bifang-public-services-onboarding/references/personal-resources.md)：自动补项目事实，先完整展示统计函数、更新函数、统计大屏、集合/索引/路由及具体配置，再让客户选择 **手动创建 / 助手自动创建并检查 / 已有资源仅检查**。复用第一门禁私有文件和 key，不重复收集。

- 手动：prepare 生成专属函数 ZIP 和私有配置，交付真实文件链接和控制台步骤；等待客户明确完成，再 verify 只读检查，不代客户创建。
- 自动：plan 展示准确目标与最新免费预检，已有明确授权覆盖该计划就直接 apply 创建、逐项和最终读回，不反复问是否开始。选择时没有具体计划则补齐后确认该计划；直接复用第一门禁准备的检查/创建权限，不再常规补关联策略；如权限已失效，返回第一门禁修复。
- 已有：跳过创建动作，按原材料或实际部署依据核验；必需项全部通过后才进第三门禁。声明已建、文件已填、旧 skipped 或仅命令退出 0 都不代表通过。部分失败停止并给逐项差异，不覆盖或删除回滚。

第二门禁通过后进入 [第三门禁](../skills/bifang-public-services-onboarding/references/personal-client-confirmation.md)：明确更新/统计范围，自动读取已有事实，把缺少的参数和运行时密钥交给客户在本地私有文件补齐。使用 `cloudbase:personal:client:init` 创建文件，填写完成后用 `cloudbase:personal:client:preview -- --file <实际路径>` 离线生成完整请求实例；正文展示脱敏实际明细，含密钥实例只保存私有文件并提供文件链接，然后等待客户明确确认。两项均选须同时通过，未确认不能编码；配置实质变化后重新确认。

第三门禁通过后进入 [第四门禁](../skills/bifang-public-services-onboarding/references/personal-client-implementation.md)，按下面四个检查点串行执行：

| 检查点      | 任务与产出                                                                                           | 进入下一步的条件                                                 |
| ----------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 4A UI 确认  | 按客户项目真实风格展示普通更新、强更、手动检查入口，列清触发/显示位置、按钮/关闭行为和强更新业务限制 | 客户明确确认本版可见 UI；仅统计无可见变更须记录不适用依据        |
| 4B 架构核验 | 阅读适用 AGENTS.md、架构/编码规范及实际模块调用链，说明复用方式、拟改范围与验证命令                  | 有文件依据的摘要完成，无阻断；自动核验，无额外人工审批           |
| 4C 本地编码 | 按确认过的请求、UI 和项目规范在目标项目实现所选服务                                                  | 前项全部通过，已有客户端实施授权且无只读限制；按既有授权直接实施 |
| 4D 本地验收 | 用假凭据和模拟传输完成适用检查与修复，交付实际变更及测试结果                                         | 所选服务及联合检查均通过，未执行项如实记录                       |

等待 UI 确认时不写业务代码，两项都接入也不先实现统计。当前个人更新默认外部链接交付，不虚构安装进度、成功状态或公司接口字段。只维护本规范不运行客户流程；真实接口、云端操作与制品测试仍须对应授权，不套用其他分支的授权中心或 EXE 流程。

第四门禁本地通过后进入 [第五门禁](../skills/bifang-public-services-onboarding/references/personal-update-preflight.md)：

需要客户填写发布信息时，助手先准备受限的目标发布交接文件，在正文给出真实绝对路径及可点击链接，并逐项列出 `release.codeVersion`、`release.downloadUrl`、`release.promptContent` 等实际缺项的完整字段路径、填写含义和必填/可选属性。已有应用/code/目标等事实预填保留；可选更新说明可留空。只给说明文档或模板路径不算交接完成。客户回复“已填写”只做本地校验，文件填写不会自动发布；校验后展示具体自动保存计划，确认后由助手保存并读回，限定预检范围按本门禁执行，字段和简短回复要求见第五门禁 reference。

| 检查点        | 动作与产出                                                                                        | 通过条件                                                 |
| ------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 5A 信息与计划 | 提供实际文件路径及缺项字段，本地校验后展示精确保存载荷、目标、读回和预检范围                      | 客户明确确认本次具体计划，未确认不写云端                 |
| 5B 自动保存   | 复核绑定，用管理 API 保存并读回；遇冲突或结果不明停止，不盲重试/覆盖                              | 保存及读回均通过，或已有一致记录核验复用                 |
| 5C 接口预检   | 在已说明范围和有效授权内请求实际更新 GET，核对 HTTP 200、七字段、映射、链接及预期行为，给脱敏结果 | 所选目标全部通过；失败由客户调整后告知重检，不能先测 EXE |

默认由助手在确认后自动保存，不让客户另外手动操作 API；客户主动选择手动时才提供该分支。预检不请求下载地址，不下载/安装/运行 EXE，不发统计、不改后台；GET 不回传目标版本号，不能把客户声明伪装成独立读回。仅统计记录本门禁更新部分不适用；都接入须先过更新预检，统计真实上报留第六步。预检通过后按 [第六步](../skills/bifang-public-services-onboarding/references/personal-artifact-testing.md) 直接执行已确认范围内的构建和基础实机测试，不重复问开始。第五门禁确认计划时一并说明后续基础测试；历史明确排除制品的限制须由客户改变，不能静默扩大。下载/安装升级和回退另按实际授权执行。

第六步完成后，助手在最终回复中一次给齐测试结果与证据、未验证项、实际制品链接和校验信息、统计大屏实际可点击地址，以及当前客户的可复制大屏登录 Token（`dashboard.DASHBOARD_ACCESS_TOKEN`）。已选统计时，逐字核对接入资料所填的中文名称、真实接口的 `appLabels[app_id]` 和页面应用选择器的可见名称，分别记录结果。不能只给私有文件路径让客户自己找凭据，也不返回 CAM、版本服务或统计查询密钥。Token 仅在当前客户最终交付中展示，不写入源码、文档、日志或 Git；缺项明确说明，仅更新时大屏项不适用。

资源工具复用第一门禁已创建的私有文件；第二门禁补齐参数后用 `cloudbase:personal:validate` 本地校验、`cloudbase:personal:plan` 只读预检。展示精确计划并取得授权后，用 `cloudbase:personal:apply` 绑定该次计划摘要创建集合、索引、三类函数和路由。命令参数及限制以第二门禁 reference 为准；同名冲突停止，已有配置不覆盖，失败不删除回滚。控制面读回不等于真实 HTTP、大屏或 EXE 测试通过。

本分支提供本地安装与更新命令，不提供个人版远端 URL bootstrap。升级已下载源码后再次运行 `npm run skill:install` 更新安装副本；不依赖本机缓存的旧版同名技能。

个人版统计保留采用普通索引与专用定时清理函数（每 15 分钟、每轮最多 100 条），包含新增 UpdateTable / CreateTrigger / ListTriggers 权限差异；完整资源与免费支持证据规则见 [清理方案](../skills/bifang-public-services-onboarding/references/retention-cleanup.md)。旧 TTL 计划不能授权新增资源或未来到期删除；新计划确认前只改本地和只读盘点。

共享函数已有其他应用时，明确选择增量接入后按[共享函数增量规范](../skills/bifang-public-services-onboarding/references/shared-function-extension.md)准备配置合并计划，保留既有应用与凭据；配置更新权限已并入第一门禁创建策略，旧账号仅在缺少该项时补齐。具体共享配置写入仍须确认计划。
