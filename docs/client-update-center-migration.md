## 门禁串行规则（2026-11-17）

门禁必须按本次已选范围严格串行：1 范围确认 → 2 授权/配置验证 → 3 完整请求明细确认 → 4A UI 确认 → 4B 架构/规范核验 → 4C 编码 → 4D 本地验收。前一步未通过，不进入下一步；两项都接入须当前门禁两项全部通过，不能让成功分支先跨门禁。仅统计无可见 UI 变更只豁免 4A 的人工确认并记录依据，其他检查点不省略。每次转入下一步先核验证据；缺项/未回复/过期不算通过，复用有效证据不重复问。门禁状态写脱敏交接记录，不添加 Profile 字段；旧运维阶段或脚本成功不能代替此链。已撤销此前联合任务中成功分支先跨门禁推进的规则，旧阶段 5 本地测试说明也不再被用作跳过真实配置验证的依据。

## 第三门禁规范（2026-11-17）

第三门禁现为“客户端接入方案与请求明细确认”：第二门禁配置验证后，按三种范围自动核验 Rust 接入位置、字段来源、默认值、迁移范围和验收计划。自动填好所选服务的接入确认单，在回复正文完整展示实际请求 URL、方法、请求头、路径/query/body 字段、必填性、非敏感实际值或动态生成规则、来源/默认值、待补项及实施验收计划；两项均选则分别完整展示。不能只给记录链接，未实施不能称已接入。凭据只展示状态和用途，不回显原值或摘要。技术就绪后必须等待客户明确确认明细；第一门禁选择或浏览器批准不代替此次确认。询问“确认并进入第四门禁／仅确认方案暂不实施／需要调整”，客户可直接授权第四门禁，不必输入阶段编号。已有只读限制不能被简单“确认”解除；未知关键项继续阻断。记录分支确认与实施授权，实质变更重新确认受影响项。主合同、Skill、AGENTS、指南及机器入口同步；它与原运维阶段 3 分开，不扩大阶段授权。

通过只表示允许在原授权内进入实施；没有实际目标项目证据时不能宣称门禁通过。已知待登记/部署/发布列线上依赖，关键映射未知停止分支；联合通过需两项均就绪。此次仅更新规范及契约检查，没有编写业务代码或执行真实接口。

## 当前 POST 协议实现

生产更新中心默认使用 `https://update.meetelf.com`；负责人明确要求本地联调时，宿主可将 SDK 的 `baseUrl` 设为 `http://127.0.0.1:8080/` 并使用本地测试 Token。Profile 与资源派生保留该实际地址；本地验证不能替代生产服务或真实客户端 E2E，不能用于完成生产发布门禁。

当前 Profile 允许的生产地址为 `https://update.meetelf.com`，地址通过授权中心返回的 Endpoint 取得并核验，不能被 SDK 内置默认值覆盖。服务端字段权威是 `bifang-client-update-center` 项目的 `docs/api/bifang-client-update-center.openapi.json`，`docs/api/client-integration.md` 和 `docs/api/client-updates.md` 补充时序。它与仓库中现有 application-version API 是不同协议，不能将域名简单替换到旧 GET 路径上。此文记录本地进度，不代表线上部署或客户端迁移完成。

公共 SDK 新增 `ClientUpdateService`：使用客户端运行时提供的 Token，向 `/api/v1/apps/{app_id}/update-checks` 发起 POST；请求由宿主提供实际版本、系统、程序架构、安装形态、持久随机 UUID、触发原因和已实现能力。返回 201 才解析决定；HTTP 错误、超时或无效响应均报告错误，不能当作已是最新版本。日志不能记录 Token 或下载链接。服务端 Token 为共享访问凭据，无法代表用户身份，也无法保证不被客户端提取。

SDK 返回 `decision`、`enforcement` 和 `action`，宿主必须按新协议处理。只有有效的 `block_new_operations` 才限制开始新业务；不可中断正在进行的业务，并须保留更新、重试和退出入口。说明文字按纯文本显示；人工下载页还须按产品允许的域名检查。`isSameInstallTarget` 只比较安装前新检测与原始检测的目标，不会验证文件或替宿主安装。

SDK 目前只实现检测和安装目标对照，**尚未实现下载、大小与 SHA-256 校验、安装前复检编排、平台安装器、强更缓存/定时、UI、持久 UUID 或自动重试**。宿主完成这些能力前不能声明对应 capabilities 或执行安装。下载时需安全处理跳转，不向外部文件域名转发 Token；安装前必须用 `pre_install` 重新检测并比较目标版本、包、大小、摘要和 action。服务端不可用时不得伪装为无更新。

本工作树已更新一键接入 Skill、Profile 校验与资源派生、宿主示例和新接入合同；这些本地变更只有经提交、推送并使规范仓库默认分支更新后，才会被严格校验来源的一句话入口使用。旧 application-version 服务和当前运营看板仍按既有配置运行。各业务客户端应在各自项目中接入并验证，不由本仓库主动修改。部署、发布、推送、构建安装和删除线上资源均需遵守现有阶段门禁。
